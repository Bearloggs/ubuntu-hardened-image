# Ubuntu hardened image

> **Use at your own risk.** Test in a non-production environment first. This baseline does not guarantee CIS, SOC2, or PCI-DSS compliance.

Packer builds a **hardened Ubuntu 24.04 LTS** image for **AWS**, **QEMU**, **VMware**, **VirtualBox**, and **Proxmox**. The same hardening scripts run on every platform; each builder adds its own guest tools.

## Operator files (gitignored)

| File | Purpose |
|------|---------|
| [`packer/local.pkrvars.hcl`](packer/local.pkrvars.hcl) | Secrets and build settings — copy from [`local.pkrvars.hcl.example`](packer/local.pkrvars.hcl.example) |
| [`packer/build-key`](packer/build-key) (+ `.pub`) | Packer build SSH (auto-generated by `make build-*` if missing) |
| [`cloud-init/instance.local.yaml`](cloud-init/instance.local.yaml) | First-boot SSH keys — copy from [`instance.example.yaml`](cloud-init/instance.example.yaml) |

```bash
make vars
cp cloud-init/instance.example.yaml cloud-init/instance.local.yaml
# edit packer/local.pkrvars.hcl and instance.local.yaml
make build-proxmox   # or build-qemu, build-aws, ...
```

Optional: `make sync-instance-key` — copy `build-key.pub` into `instance.local.yaml`.

## Build

```bash
make help
make vars
# edit packer/local.pkrvars.hcl (uncomment your platform block)
make build-<platform>
```

Platforms: `aws`, `qemu`, `proxmox`, `vmware`, `virtualbox`. See [Platform builds](#platform-builds).

### Make targets

| Target | Action |
|--------|--------|
| `make vars` | Create `packer/local.pkrvars.hcl` from example |
| `make build-<platform>` | Init + keys + hash + packer build |
| `make build-<platform>-debug` | Same, with `-on-error=ask` |
| `make validate-<platform>` | `packer validate` |
| `make build-key` | Generate `packer/build-key` |
| `make sync-instance-key` | Copy `build-key.pub` → `instance.local.yaml` |
| `make clean` | Remove caches and outputs |

`PACKER_EXTRA_ARGS='-only=...'` for extra flags.

### Packer (manual) {#packer-manual}

```bash
cd packer/<platform>
packer init .
packer build -var-file=../local.pkrvars.hcl .
```

### Build SSH access

| Platform | Build SSH auth |
|----------|----------------|
| **AWS** | Packer temporary ED25519 key pair on the AMI |
| **QEMU, Proxmox, VMware, VirtualBox** | `packer/build-key` — required; password SSH disabled (`allow-pw: false`) |

## Platform builds

All platforms use the same operator files: [`packer/local.pkrvars.hcl`](packer/local.pkrvars.hcl) and [`packer/build-key`](packer/build-key). After build, see [First-boot SSH access](#first-boot-ssh-access) for launch. Manual Packer: see [Packer (manual)](#packer-manual).

### Proxmox VE

Uncomment the `# --- Proxmox ---` block in `packer/local.pkrvars.hcl` (`proxmox_url`, `proxmox_password`, `proxmox_node`, `proxmox_iso_storage_pool`).

```bash
make build-proxmox
```

Installs `qemu-guest-agent` via [`scripts/platform/proxmox.sh`](scripts/platform/proxmox.sh).

**First boot:** Proxmox Cloud-Init UI — use [`cloud-init/instance.local.yaml`](cloud-init/instance.local.yaml). [Details](#proxmox-ve-1).

### QEMU (qcow2)

Uncomment `# --- QEMU ---` in `packer/local.pkrvars.hcl` if needed (`qemu_accelerator = "tcg"` for nested VMs without KVM).

```bash
make build-qemu
```

Output: `output-qemu/*.qcow2` at the repo root.

**First boot:** NoCloud `cidata` seed — [QEMU / KVM / libvirt](#qemu--kvm--libvirt).

### AWS (AMI)

Uncomment `# --- AWS ---` in `packer/local.pkrvars.hcl`. Configure AWS credentials in the environment.

```bash
make build-aws
```

Packer uses a temporary ED25519 key during the build; bootstrap keys are cleared on the AMI.

**First boot:** EC2 key pair or user-data — [AWS](#aws).

### VMware

Uncomment `# --- VMware ---` in `packer/local.pkrvars.hcl`.

```bash
make build-vmware
```

Output: `output-vmware/`

**First boot:** guestinfo or OVF — [VMware](#vmware-1).

### VirtualBox

Uncomment `# --- VirtualBox ---` in `packer/local.pkrvars.hcl`.

```bash
make build-virtualbox
```

Output: `output-virtualbox/`

**First boot:** NoCloud `cidata` or console — [VirtualBox](#virtualbox-1).

## Repository layout

| Path | Purpose |
|------|---------|
| [`packer/local.pkrvars.hcl.example`](packer/local.pkrvars.hcl.example) | Template for operator settings (all platforms) |
| `packer/<platform>/` | Packer builder + plugins (symlinks to `packer/_shared/`) |
| `packer/_shared/` | Shared variables and cloud-init locals |
| `cloud-init/nocloud/` | Build-time NoCloud templates (autoinstall + cloud-image) |
| [`cloud-init/instance.example.yaml`](cloud-init/instance.example.yaml) | First-boot user-data template |
| `scripts/base/` | Hardening scripts |
| `scripts/platform/` | Per-platform guest tools |

**Cloud-init:** `cloud-init/nocloud/` is used only during `make build-*` (Packer). After the image exists, use `cloud-init/instance.local.yaml` for new VMs (Proxmox Cloud-Init UI or NoCloud CD).

Do **not** reuse the Packer build `instance-id` (`iid-packer-ubuntu-hardened`) on production VMs — see [First-boot SSH access](#first-boot-ssh-access).

### Key variables

In [`packer/_shared/variables.pkr.hcl`](packer/_shared/variables.pkr.hcl) and `packer/local.pkrvars.hcl`:

| Variable | Default | Purpose |
|----------|---------|---------|
| `build_ssh_username` | `ubuntu` | OS user for Packer SSH |
| `build_ssh_private_key_path` | `packer/build-key` | Override build SSH key path |
| `cloud_init_instance_id` | `iid-packer-ubuntu-hardened` | Build-time NoCloud instance-id only — see [Use a new instance-id](#use-a-new-instance-id) |
| `initialize_aide` | `false` | Run aideinit during build (slow) |

## First-boot SSH access

Built images are sanitized: **password SSH is disabled**, **host keys are removed**, and **bootstrap authorized_keys are cleared** during cleanup. Supply SSH keys on first boot via cloud-init, or use console / hypervisor access as a fallback.

### Operator file

Copy [`cloud-init/instance.example.yaml`](cloud-init/instance.example.yaml) to `cloud-init/instance.local.yaml` (gitignored), add your SSH public key, and attach at launch.

Optional: `make sync-instance-key` copies `packer/build-key.pub` into `instance.local.yaml` (same key as the Packer build).

```yaml
#cloud-config
hostname: my-host
ssh_authorized_keys:
  - ssh-ed25519 AAAA... your-key ... you@host
package_update: false
package_upgrade: false
```

### Use a new instance-id

Packer uses a fixed NoCloud `instance-id` (default: `iid-packer-ubuntu-hardened`). **Do not reuse it** on production instances — cloud-init may skip user-data.

For NoCloud/CD, uncomment in `instance.local.yaml`:

```yaml
# instance-id: iid-myhost-001
# local-hostname: my-host
```

Proxmox assigns a new instance-id per VM automatically.

### Proxmox VE

1. Add a **Cloud-Init** drive (or cloud-init tab in the VM wizard)
2. Paste `cloud-init/instance.local.yaml` (or SSH key only)
3. User: `ubuntu` by default

### AWS

- EC2 key pair at launch (recommended), or user-data with `ssh_authorized_keys`
- SSM Session Manager if SSM agent was installed during build

### QEMU / KVM / libvirt

Create `cidata.iso` from meta-data + user-data:

```bash
mkdir -p /tmp/cidata
# meta-data: instance-id + local-hostname (from instance.local.yaml comments)
cp cloud-init/instance.local.yaml /tmp/cidata/user-data
# add /tmp/cidata/meta-data
genisoimage -output cidata.iso -volid cidata -joliet -rock /tmp/cidata/user-data /tmp/cidata/meta-data
```

Attach `cidata.iso` when starting the VM from the built `.qcow2`.

### VMware

Inject user-data via **guestinfo** (`guestinfo.userdata` / `guestinfo.metadata`) or OVF properties.

### VirtualBox

NoCloud `cidata` ISO (same as QEMU), or hypervisor console as fallback.

### Troubleshooting

| Symptom | Likely cause |
|---------|----------------|
| SSH connection refused on port 22 | VM not booted, UFW blocking (only 22 open), or sshd not up |
| Permission denied (publickey) | No key on first boot; password auth is off |
| Host key verification failed | Host keys regenerate on first boot; update `known_hosts` |
| cloud-init did not apply user-data | Reused Packer `instance-id`; supply a new one |

```bash
sudo cloud-init status
sudo journalctl -u cloud-init
```

## What gets hardened

- Updates: `dist-upgrade`, security-only `unattended-upgrades`
- Network: UFW (deny inbound, SSH rate-limited), kernel sysctls
- Access: SSH key-only, PAM faillock, password quality rules
- Monitoring: auditd, fail2ban, journald, optional AIDE
- System: AppArmor, CIS module blacklist, GRUB cmdline
- Cleanup: logs, caches, blank `machine-id`, SSH host keys removed

## Hardening checklist

Use before promoting an image to production. **build** = Packer; **you** = after deploy.

### Build configuration

- [ ] `make vars` and [`packer/local.pkrvars.hcl`](packer/local.pkrvars.hcl) reviewed (platform section uncommented)
- [ ] `packer/build-key` (+ `.pub`) present (`make build-key` or auto on build)
- [ ] No secrets committed (`local.pkrvars.hcl`, `build-key`, `instance.local.yaml`)

### Applied at build

- [ ] **build** Patched system, security-only unattended-upgrades
- [ ] **build** UFW, SSH hardening, kernel/GRUB, auditd, fail2ban, AppArmor
- [ ] **build** Cleanup — logs, machine-id, host keys removed

### Before production

- [ ] **you** [`cloud-init/instance.local.yaml`](cloud-init/instance.local.yaml) ready for first boot ([First-boot SSH access](#first-boot-ssh-access))
- [ ] **you** New cloud-init `instance-id` (not `iid-packer-ubuntu-hardened`)
- [ ] **you** Instance boots; SSH or console works
- [ ] **you** Required UFW ports open
- [ ] **you** Application runs cleanly
- [ ] **you** CIS-CAT or OpenSCAP ([CIS benchmark mapping](#cis-benchmark-mapping))

## CIS benchmark mapping

Scripts implement a **subset** of the [CIS Ubuntu Linux 24.04 LTS Benchmark](https://www.cisecurity.org/cis-benchmarks). This is not full CIS L1/L2 certification — run CIS-CAT on a deployed instance for formal assessment.

AWS AMIs are tagged `CIS_Level = oriented` for inventory purposes only. That tag does **not** indicate CIS Level 1 or Level 2 certification.

| CIS section | Topic | Script |
|-------------|-------|--------|
| 1.1 | Filesystem / module restrictions | `02b-modprobe-blacklist.sh`, `07-fstab-hardening.sh` |
| 1.2–1.3 | Updates, AppArmor | `01-update.sh`, `02-hardening.sh`, `02c-apparmor.sh` |
| 1.4–1.5 | Boot / process hardening | `04b-grub-hardening.sh`, `04-kernel-hardening.sh` |
| 2.x | Services, time sync | `02-hardening.sh`, `05e-journald-time.sh` |
| 3.x | Network, firewall | `04-kernel-hardening.sh`, `02-hardening.sh` |
| 4.x | auditd, logging | `05-audit.sh`, `05e-journald-time.sh` |
| 5.x | SSH, PAM, accounts | `03-ssh-hardening.sh`, `02d-pam-accounts.sh` |
| 6.x | AIDE | `05b-aide.sh` |

Not covered in-image (handle separately): interactive root password, GRUB password, full CIS scoring, workload-specific ports and services.
